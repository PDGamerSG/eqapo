# eqapo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver `eqapo`: a background macOS daemon that applies Equalizer APO configuration files to all default-output audio, plus PC Equalizer's presets and a menu-bar front end.

**Architecture:** A portable C++20 engine re-implements Equalizer APO's filter engine (same factories, routing, crossfade, filter math). An Objective-C++ daemon feeds it from a Core Audio process tap inside a private aggregate device and writes the result to the real output device. A Swift menu-bar app and a CLI write PC Equalizer-format `config.txt`.

**Tech Stack:** C++20, Objective-C++, CoreAudio (`AudioHardwareTapping.h`, aggregate devices), AudioToolbox (`ExtAudioFile`), Accelerate (vDSP FFT), CoreServices (FSEvents), CMake 3.25+/CTest, Swift 6 + SwiftUI (`MenuBarExtra`), launchd LaunchAgent.

**Spec:** `docs/superpowers/specs/2026-10-23-eqapo-mac-design.md`

## Global Constraints

- macOS 14.2 minimum (process taps); build host macOS 27, Command Line Tools only (no Xcode).
- No third-party libraries. System frameworks only.
- Audio thread: no allocation, no locks, no logging, no Objective-C messaging.
- Filter math and config semantics must match Equalizer APO 1.4 (spec §4.2) exactly.
- All user-facing paths under `~/Library/Application Support/eqapo/`.
- Binary name `eqapo`; bundle id `com.eqapo.daemon`; GUI bundle `com.eqapo.gui`.
- License GPL-2.0-or-later; no code copied from Equalizer APO.
